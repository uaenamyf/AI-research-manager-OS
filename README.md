## ❓ Why ResearchOS

Most "AI research" tools give you a chat box. **ResearchOS** gives you the **full research loop on top of a real agent harness**:

- **Workspace code-diff side panel** — see the changes between commits/files/submodules inside the workbench, not in a separate Git client.
- **Per-user research LLM configuration** — set the model, base URL, and API key for *paper parsing*, *writing*, *review*, and *embedding* in **Settings → 研究区大模型**. Per-user override beats the system default.
- **Real-time import progress** — when you import a paper from online search or upload, the dialog shows a live progress bar and the actual error on failure (not a silent "FAILED" you only discover later).
- **Auto-Paper Card** — the moment a PDF is parsed, a structured "Paper Intelligence Card" is generated by the LLM and stored next to the chunk index.
- **Literature review in one click** — multi-select any papers across projects → generate a Markdown review in the background, watch the task progress.
- **MCP-exposed literature search** — the literature MCP server is callable from any DSH agent, not only the research UI.
- **Everything is a DSH plugin** — every piece is a Cordis-style `apply(ctx)` plugin; nothing is hard-wired.

It runs on a single Node process, talks to a single SQLite file, and survives `git clone + pnpm install + pnpm run build` without any infrastructure.

The full architecture mirrors the [DSH official architecture doc](docs/architecture.md) — a plugin tree rooted at `ctx.webServer` (server bundles) and `ctx.slots` (UI packages). The "everything is a plugin" rule holds: removing any `research-*` package does not break the rest.

## 🚀 Quick start (clone-and-run)

**Prerequisites**: Node.js ≥ 22.5 (24+ recommended), pnpm, git.

```sh
git clone https://github.com/uaenamyf/AI-research-manager-OS.git
cd AI-research-manager-OS
pnpm install          # postinstall 自动构建 literature-search-mcp vendor
pnpm run build
pnpm dsh web          # → http://localhost:3080
```

Open <http://localhost:3080>. **No login, no signup** — it opens the research workbench directly. The SQLite database and upload directory are created on first start.

> Configure your research LLM + embedding in **Settings → 研究区大模型** — that's the primary path, persisted per user (SQLite `app_user.settings.research`) and read by every parse/review/write/embed job. Leave fields empty to fall back to the built-in defaults (Volcengine Ark endpoint). An optional `packages/researchos/.env` (copy of `.env.example`) can supply system-wide defaults, but is **not required** — the UI settings are enough.

Useful commands (`make -C packages/researchos help` for the full list):

| Command | Effect |
|---------|--------|
| `pnpm dsh web` | Launch the research workbench (default `:3080`) — the recommended way |
| `make -C packages/researchos start-dsh` / `stop-dsh` | Same as above via the legacy shell wrapper (background daemon, PID file) |
| `make -C packages/researchos status` / `logs` | Process status / tail log (shell wrapper) |
| `make -C packages/researchos reset` | Wipe local data (SQLite + uploads) |

> The old `make start-dsh` path is kept for daemon-style usage; `pnpm dsh web` is now the primary entry — it bootstraps researchos env + vendor automatically.

## 🔬 ResearchOS innovations (what this fork adds on top of DSH)

ResearchOS is a DSH plugin suite, not a fork of DSH itself. All the changes below are pure additions under `packages/researchos/` (zero merge conflict with upstream DSH).

### 1. The research workspace side panel

- `ui-research-workspace` slots into the DSH sidebar (replaces half of it) and into the details column (replaces the conversation details panel via `priority: -100` shadowing).
- Right-edge IDEA-style tool window rail (`#research-railbar`, `position: fixed`, 46px wide) — click the rail to fold/unfold the details column without losing the conversation.
- Three-pane layout: **left: literature library** (projects · folders · papers with status dots) / **right: paper details** (PDF preview, Paper Card, online search, review, writing) / **center: conversation**.
- Drag a paper from the library → drop into the conversation input → attaches it as a file context (`[研究区论文] <title>（论文 #<id>）`).
- Draggable file previews: drag a workspace file from the right column into the chat composer.

### 2. Workspace code diff inside the research workbench

- `research-workspace` bundle exposes `GET /research-workspace/overview` and `GET /research-workspace/diff` for any **DSH-registered workspace** (DSH `ctx.workspaces`).
- Renders side-by-side **commit / file / submodule** navigation: click a submodule entry to enter its tree (it auto-folds to root), the back button (`WSIconBack`) returns to the parent.
- Folder counts + per-top-dir scan quotas prevent an N×M file explosion on monorepos.
- Click a file → patch/diff view (uses the DSH `worker` runtime; no separate Git client).
- Per-directory file-type icons; search filter; file-size metadata.

### 3. Online literature search (multi-source MCP)

- `research-external-search` is a thin REST wrapper around the vendor `literature-search-mcp` ([`packages/researchos/external-search/vendor/literature-search-mcp/`](packages/researchos/external-search/vendor/literature-search-mcp/)).
- **Sources**: PubMed · EuropePMC · Crossref · OpenAlex · Semantic Scholar · arXiv · bioRxiv.
- Free-text, title-phrase, author, DOI, year-range, and "open-access only" filters.
- Every result card exposes `pdf_url`; clicking **「导入到研究区」** opens the import dialog. The import dialog shows **live progress** and the **actual failure reason** on error.
- Browser-side `/research-external-search/pdf?url=...` proxy (with browser UA / Referer) bypasses paywall bots on arxiv / europepmc / wiley etc.

### 4. Inline AI pipeline (no RabbitMQ, no queue)

- `research-ai-worker` is invoked **inline** by the paper / review bundles — no MQ, no extra process. See [analyze.js](packages/researchos/ai-worker/lib/analyze.js).
- Six-step pipeline per paper: **download PDF → parse+chunk → embed → write SQLite → generate Paper Card → READY**.
- Per-paper **status** (UPLOADED / PROCESSING / READY / FAILED) + **error** in `paper.summary` (the worker's `setPaperStatus` writes `{ error }` on failure).
- Per-user override: `getUserResearchSettings(pool, paper.user_id)` runs at step 1, so the LLM and embedding model used for this paper are the ones configured in **Settings → 研究区大模型**.

### 5. Per-user research LLM settings

- New `settings.section` registrant: id `research-models`, order 20 (right after the DSH `ui-settings-models`).
- Form: LLM (Base URL · 模型名称 · API Key) + Embedding (Base URL · 模型名称 · API Key). API Key is a password input — it is **not echoed after save**; leaving it empty preserves the stored key.
- Persisted via `PATCH /research-settings` → `app_user.settings.research.{llm,embedding}` (SQLite JSON column).
- Read on every `analyze` and `embedBatch` call.

### 6. Real-time import progress dialog

- When you click "导入" on an online search card, the import dialog stays open and **polls `GET /research-paper/papers/:id` every 3 s** (6 min cap) until READY or FAILED.
- PROCESSING: animated progress bar + "下载 → 解析 → 向量化 → 生成卡片".
- READY: green bar + "导入成功 ✓ 已就绪" → auto-close + refresh tree after 1.2 s.
- FAILED: red bar + the **actual error string** (e.g. `pdf download failed: ...timeout`); the OK button becomes "关闭" so the user can read it.

### 7. Unified LLM / Embedding gateway

- `research-llm-gateway` exposes `/v1/chat/completions` and `/v1/embeddings` as **OpenAI-compatible** endpoints on the same DSH port.
- `pnpm dsh web` bootstraps researchos env (from `packages/researchos/.env`, auto-created from the example) via `packages/researchos/scripts/researchos-bootstrap.mjs`; the gateway serves `/v1/chat/completions` + `/v1/embeddings` on the same port. Per-user overrides (`user_id`) ride on the request.
- Falls back gracefully: if the user override fails (bad key, bad URL), the worker logs and retries with the system default.

### 8. research-mcp (DSH agent tool)

- The literature MCP is registered as `dsh-mcp-client` row; available tools:
  - `literature_search({ q, title, author, doi, year_from, year_to, open_access })` → list of papers with PDF URLs
  - `literature_get({ id | doi | pmid })` → metadata + PDF URL
  - `literature_cite({ id, format })` → BibTeX / APA / MLA
  - `vector_search({ query, top_k })` → cosine search over the local `paper_chunk` BLOB store
- Any DSH agent (Cordis / `subagent` / `agent-loop`) can call these directly.

### 9. No login, no subscription, no Docker, no MQ

- Anonymous local mode: `GET /research-auth/anon` issues an httpOnly cookie bound to a single demo user. No signup, no password reset, no OAuth.
- Removed: `research-subscription` (Stripe), Google OAuth, `infra/docker-compose.yml`, RabbitMQ producer/consumer.
- Everything else runs on a single Node process + a single SQLite file.

## 🧱 Repo layout

This repository is a **single repo**: the DSH full source is at the root; ResearchOS lives entirely under [`packages/researchos/`](packages/researchos/README.md). DSH sources are pulled from `deepseek-ai/deepseek-harness` via [`bash packages/researchos/scripts/upgrade-dsh.sh <tag> [--push]`](packages/researchos/scripts/upgrade-dsh.sh) (fetch upstream tag → merge → build → vitest → push main).

```
packages/researchos/
├── server/            # research-* server bundles（auth / project / folder / paper /
│   └── bundles/       # file / writing / review / paper-card / export / settings / workspace）
├── ai-worker/         # 内联 AI 管道：解析 → 分块 → 嵌入 → 生成卡片
├── llm-gateway/       # 统一 LLM/Embedding 网关（OpenAI 兼容，key 单点收口）
├── mcp/               # research-mcp：stdio MCP server，供 DSH agent 检索
├── ui/                # ui-research-* 客户端包
├── external-search/   # 在线文献检索（多源 MCP 包装）
├── lib/               # SQLite 抽象层（db.js：schema + 向量检索）
├── scripts/           # researchos-bootstrap.mjs（env+vendor 引导）、build-vendor.mjs、
│                      #   upgrade-dsh.sh（上游升级）、dsh-gateway.sh（守护进程式启停）
├── Makefile           # start-dsh / stop-dsh / status / logs / reset
└── README.md          # 模块级 README（本文件同级）
```

DSH-side docs that are *not* part of ResearchOS (and are kept verbatim from upstream so users of the underlying harness can still navigate the repo) include `AGENTS.md`, `CLAUDE.md`, `BRAND_GUIDELINES.md`, `CONTRIBUTING.md`, `docs/architecture.md`, `docs/cordis-primer.md`, `docs/agent-lifecycle.md`, `docs/defensive-patterns.md`, `docs/event-producer-consumer.md`, `docs/glossary.md`, `docs/graph-atlas.md`, `docs/module-graph.md`, `docs/persistence-catalog.md`, `docs/rescope.md`, `docs/testing.md`, `docs/tool-catalog.md`, `docs/tool-execution-pipeline.md`, `docs/web-styling.md`, and the postmortem index in `docs/postmortem/`. These describe **the host harness**, not the research module.

## 🧪 Testing & quality

- **CI** (`.github/workflows/researchos-ci.yml`) runs on every push: `node --check` on every server bundle, AI worker, gateway, MCP, and external-search module + SQLite schema sanity check.
- `packages/researchos/TESTING.md` is intentionally not shipped — testing is performed by the CI workflow and the DSH vitest suite (the local runner scripts in `scripts/dsh-gateway.sh` cover end-to-end smoke).
- LLM-related code keeps its callers mockable; CI never consumes real tokens.

## � Roadmap

ResearchOS is evolving fast. Planned next milestones (subject to change):

- **AutoResearch (autoresearch)** — an autonomous research agent loop: given a topic or research question, the agent searches the literature across all connected sources, curates the most relevant papers, and writes a structured research paper on the specified theme — all fully automatic, with citation tracking and section drafting.
- **Agent-driven full-pipeline writing** — the DSH agent takes a topic → retrieves & filters papers → outlines → drafts each section → formats citations (BibTeX/APA/MLA) → produces a submission-ready manuscript.
- More to come: literature review quality scoring, citation graph visualization, and deeper `research-mcp` tooling for agents.

Ideas, feature requests, and PRs are very welcome — open an issue or a discussion to shape the roadmap.
